--------------------------------------------------------------------------------
1. PROJECT GOAL & CONTEXT
--------------------------------------------------------------------------------

Aim 2 develops and validates patent-protected AI that optimizes auricular VNS
parameters using multi-modal physiological data. The Phase 1 scope is an
offline-trainable, online-capable inference pipeline that:
- Ingests multi-modal physiological data (ECG/PPG from PhysioNet, MIMIC-III).
- Processes HRV via wavelet transforms and time/frequency/non-linear features.
- Runs a Hybrid Ensemble (CNN + RNN + Transformer) for classification.
- Outputs state-machine controlled trigger commands to the Sparrow Link (Phase 1
  uses MockSparrow; real hardware deferred to Live Integration).

Why this scope: Establish algorithm robustness and generalizability on large
datasets before live hardware integration; meet NFRs (e.g. AUROC ≥ 0.75,
latency < 200 ms) in a controlled environment.

--- 2.3 Preprocessing & Feature Extraction (100%) ---

- src/features/wavelet_filter.py
  - CWT (PyWavelets) denoising: removes baseline wander (<0.5 Hz) and
    high-frequency noise (>45 Hz). Wavelet family and scale range from
    config.yaml (e.g. cmor, scale_range [1, 64]) — FR-2.1.
  - Choice of CWT: balances time-frequency localization for physiological
    signals and aligns with Aim 2 “wavelet transformation for signal denoising
    and adaptive filtering.”

- src/features/artifact_scrubber.py
  - should_reject_window(): rejects windows where amplitude exceeds X×MAD or
    any R–R interval deviates from local median by >Y%. X, Y in config
    (amplitude_mad_multiple: 5, rr_deviation_percent: 25) — placeholders to be
    updated per validation.
  - MAD-based amplitude: robust to outliers; R–R deviation catches ectopy and
    artifact that would distort HRV.

- src/features/peak_detector.py
  - R-peak detection via neurokit2 (e.g. nk.ecg_peaks) to obtain R–R
    intervals for HRV.

- src/features/hrv_time.py
  - Time-domain HRV: RMSSD, SDNN from R–R intervals (standard indices).

- src/features/hrv_freq.py
  - Frequency-domain HRV: LF, HF, LF/HF ratio via Welch’s method (scipy.signal).

- src/features/hrv_nonlinear.py
  - Non-linear HRV: e.g. sample entropy, DFA α1; integrated into pipeline per
    Aim 2.

- src/features/pipeline.py
  - High-level pipeline: one 5-min waveform → sequence of HRV vectors for RNN.
  - Feature order fixed: rmssd, sdnn, lf, hf, lf_hf_ratio, sampen, dfa_alpha1
    (7 features). Rejected or insufficient windows yield NaN rows; pipeline
    uses config subwindow_sec (30 s) → 10 time steps over 5 min (hrv_seq_len in
    config).
  - Orchestrates: denoise → peak detection → artifact check → time/freq/
    nonlinear HRV per subwindow.

- src/features/scaler.py
  - Z-score standardization with sklearn StandardScaler. Fit on training set
    only; persist to models/artifacts/scaler.pkl. Live inference must load this
    same scaler to avoid train/test leakage and ensure consistent feature
    scale (NFR-3.1, TR-1.1).

--- 2.4 Hybrid AI Models — PyTorch (100%) ---

- src/models/cnn.py
  - 1D-CNN (nn.Conv1d) for 10-second raw waveform. Returns 128-dim embedding
    (config: cnn_embed_dim). Role: morphology and robust feature extraction
    from raw waveform (FR-3.1; Aim 2 “≥80% cross-dataset accuracy” for CNN).

- src/models/rnn.py
  - GRU (nn.GRU) over 5-minute sequences of HRV features (10 steps × 7
    features). Returns 64-dim hidden state (config: rnn_hidden_size). Role:
    temporal pattern recognition and state evolution (FR-3.2).

- src/models/transformer.py
  - nn.TransformerEncoder over the same HRV sequence. Role: attention-based
    weighting of time steps and parameter optimization (FR-3.3; Aim 2
    “≥85% parameter optimization” for Transformer).

- src/models/ensemble.py
  - HybridEnsemble: concatenates CNN, RNN, and Transformer embeddings into a
    single FC layer → single logit for BCEWithLogitsLoss (binary classification).
  - Fused dim = cnn_embed_dim + rnn_hidden_size + transformer_d_model (e.g.
    128 + 64 + 64). Dropout (0.2) for regularization.
  - Rationale: multi-architecture fusion per Aim 2 “≥90% overall
    classification” and “integrated decision-making via multi-architecture
    fusion and real-time processing.”

- src/models/pca_reduction.py
  - PCA (sklearn) to map multi-channel (e.g. Galea 8-channel) to 1-channel
    equivalent for Sparrow. Single-channel data: pass-through. Supports
    TR-2.3 (strip 80% channels, verify ≥75% baseline accuracy) and future
    Galea→Sparrow integration.

--- 2.9 Background: HRV Feature Sparsity (identified 2026-03-13) ---

Precomputed cache analysis (157,337 train samples × 10 timesteps = 1,573,370
HRV rows) reveals severe feature sparsity:

  Feature 0-1 (RMSSD, SDNN):       173,647 valid rows (~11%)
  Feature 2-4 (LF, HF, LF/HF):        545 valid rows (~0.03%)
  Feature 5-6 (SampEn, DFA α1):          0 valid rows (0%)

The model is currently training with features 5-6 zeroed out entirely
(NaN → 0 after scaling) and features 2-4 effectively zeroed out. The
CNN branch (raw 10s waveform) is carrying nearly all classification signal.
The RNN and Transformer branches receive mostly zeros.

ROOT CAUSES (three independent issues):

  1. Artifact scrubber R-R deviation threshold rejects AF windows.
     artifact_scrubber.py rejects any window where an R-R interval deviates
     >25% from the local median (config artifact.rr_deviation_percent: 25).
     AF is defined by irregularly irregular R-R intervals — RR variability
     of 40-60% is typical in AF. This means the scrubber systematically
     rejects AF windows, which are exactly the positive class we need to
     classify. This is the primary cause of the ~89% NaN rate in time-domain
     features (RMSSD/SDNN). Normal sinus rhythm windows also get rejected
     when respiratory sinus arrhythmia causes transient RR variation > 25%.

  2. 30-second subwindow is too short for frequency-domain HRV.
     hrv_freq.py requires MIN_SAMPLES = 64 R-R intervals for Welch PSD.
     At a normal heart rate of 60-100 bpm, a 30s window produces only
     ~30-50 beats → ~29-49 R-R intervals, well below 64. LF power
     (0.04-0.15 Hz) also has a fundamental resolution problem: one full
     LF cycle takes 7-25 seconds, so a 30s window captures at most 1-4
     cycles — not enough for reliable spectral estimation. This is why
     only 545 out of 1.57M rows have valid frequency features (those 545
     are from subjects with very high heart rates).

  3. Nonlinear features need longer time series.
     SampEn and DFA α1 (via neurokit2) require sufficient embedding
     dimensions and data length to converge. With ~30 R-R intervals per
     30s window, neurokit2 silently returns NaN or fails. SampEn typically
     needs ≥200 data points for stable estimates; DFA needs ≥100.

RECOMMENDED FIXES (in order of priority):

  A. Fix the artifact scrubber for AF data (highest priority).
     The current R-R deviation threshold defeats the purpose of the
     classifier. Options:
       (a) Increase rr_deviation_percent to 60-80% (allows AF-typical
           variability while still catching gross artifacts like lead-off).
       (b) Disable R-R rejection entirely and rely on amplitude-MAD only.
           R-R irregularity is a feature for the model, not an artifact.
       (c) Use a two-stage approach: compute HRV with relaxed thresholds
           for the AI pipeline; apply strict R-R checks only for the
           safety/watchdog layer (FR-4.2) before stimulation.
     This fix alone should raise time-domain feature coverage from ~11%
     to 60-80%+.

  B. Increase subwindow_sec from 30s to 60s (recommended compromise).
     60s at 70 bpm → ~70 R-R intervals, just above MIN_SAMPLES = 64.
     This gives 5 time steps per 5-min window (vs current 10), which is
     still reasonable for RNN/Transformer temporal modeling. Trade-off:
     coarser temporal resolution, but far more valid frequency features.

     Alternative: 120s subwindow → ~140 R-R intervals (solidly above 64),
     but only 2-3 time steps — too few for the RNN to learn sequences.
     60s is the best balance.

     If 60s is used, update config:
       hrv.subwindow_sec: 60
       model.hrv_seq_len: 5
     And rebuild the cache (python -m src.training.precompute_cache).

  C. Lower MIN_SAMPLES in hrv_freq.py from 64 to 32 (quick win).
     Combined with fix B (60s window), this gives comfortable margin.
     Welch's method with nperseg=min(256, len//2) still works at 32
     samples; spectral estimates will be noisier but the model can learn
     to weight them appropriately.

  D. Tiered feature windows (future enhancement, not urgent).
     Use 30s subwindows for time-domain HRV (RMSSD/SDNN need only ~10 RR
     intervals) and compute frequency/nonlinear features once over the
     full 5-min window as static features appended to each timestep. This
     maximizes temporal resolution for time-domain while giving
     frequency/nonlinear features enough data. Requires pipeline refactor.

  E. Accept CNN-dominant training for now (pragmatic short-term).
     The current training run will produce a model where the CNN branch
     dominates (it sees raw waveform morphology — P-wave absence, f-waves,
     irregular R-R — which are strong AF signals). The RNN/Transformer
     branches contribute little with zeroed HRV. This is acceptable as a
     Phase 1 baseline: if CNN-only AUROC meets NFR-2.1 (≥0.75), then
     fixing HRV coverage is an enhancement, not a blocker.

--- 2.10 Deep Pipeline Audit (2026-03-13) ---

Cache rebuild was in progress (~67%, ~3.5 hrs) when deep audit revealed 5 additional
issues that would invalidate the cache. Process killed to avoid wasting time. All
fixes to be applied before a single rebuild.

ISSUES FOUND:

  1. CRITICAL: Mixed sampling rates create model bias.
     AF records (afdb) are 250 Hz; NSR records (nsrdb) are 128 Hz. The CNN
     receives raw waveform — AF always produces 2500 samples (250×10s), NSR
     always produces 1280 samples (128×10s). After padding to uniform length,
     the model can trivially learn the padding pattern as a proxy for the label.
     This also biases HRV: peak detection at 128 Hz has coarser temporal
     precision than at 250 Hz, introducing systematic feature-scale differences
     between the two classes independent of physiology.
     FIX: Resample all signals to uniform 250 Hz in dataset_parsers.py using
     scipy.signal.resample. Added target_fs: 250 to config.yaml.

  2. CRITICAL: Artifact rejection rejects valid AF windows (np.any logic).
     artifact_scrubber.py line 55: np.any(dev_pct > rr_deviation_percent)
     rejects a window if ANY single beat deviates >60% from median RR. AF is
     defined by irregularly irregular RR — this systematically rejects the
     positive class. Aim 2 methodology explicitly says "artifact detection and
     correction" not rejection.
     FIX: (a) New correct_rr_intervals() function that interpolates outlier
     beats instead of discarding the window. (b) Change should_reject_window()
     from np.any to fraction-based: reject only if >30% of beats deviate.
     Added rr_fraction_threshold: 0.30 to config.yaml.

  3. HIGH: SampEn and DFA always NaN (0% valid across 1.57M rows).
     compute_hrv_nonlinear() calls neurokit2's entropy_sample (needs ~200 RR
     intervals) and hrv_nonlinear/dfa (needs ~100). With 60s subwindow at
     ~70 bpm = ~70 RR intervals — well below both thresholds.
     FIX: Compute nonlinear features once over the full 5-min RR pool (~350
     intervals at 70 bpm) and broadcast to all timesteps. Trades temporal
     resolution for valid features. Time/freq features remain per-subwindow.

  4. HIGH: NaN→0 masks data loss with no logging.
     precompute_cache.py line 161: np.nan_to_num(hrv, nan=0.0) converts all
     remaining NaN to zero. Model can't distinguish true zero variability from
     missing data. After fixes 1-3, NaN count should drop from ~89% to <10%.
     FIX: Add logging of NaN % before imputation so we can track improvement.

  5. MAJOR: Non-overlapping windows waste ~50% of small dataset.
     With only 41 records, non-overlapping 10s stride wastes potential training
     data. PhysioDataset already accepts stride_sec (line 28-32) but
     get_dataloaders() doesn't expose it.
     FIX: Add stride_sec: 5 to config.yaml, wire through get_dataloaders()
     for training set only (val/test stay non-overlapping for unbiased eval).

DECISION: Kill cache rebuild, fix all 5 issues, then rebuild once.
See PLAN.md Steps 6-13 for implementation order and details.

TRAINING STRATEGY AFTER FIXES:

  1. Apply fix A (relax artifact scrubber) + fix B (60s subwindow) + fix C
     (lower MIN_SAMPLES) → rebuild cache → retrain. Compare AUROC to
     CNN-only baseline.
  2. If AUROC improves, the RNN/Transformer branches are contributing.
     If not, investigate whether the HRV features add information beyond
     what the CNN already captures from raw waveform.
  3. Scaler was updated to fit per-column (not requiring all 7 features
     valid per row) on 2026-03-13. This is in src/features/scaler.py.

ADDITIONAL NOTE — Scaler fix applied 2026-03-13:

  The original fit_scaler() required all 7 features to be non-NaN in a row
  to include it in the scaler fit. With 0 fully-valid rows, this caused a
  hard failure. Fixed to fit per-column: each feature's mean/variance is
  computed from its own valid entries. This allows training to proceed even
  with sparse features.

--- 2.11 Training Loop Quality Fixes (2026-03-14, post-audit) ---

Senior ML engineer audit of the full codebase identified 7 issues in the
training loop and model code. None of these affect the precompute cache —
all changes are in training code, model defaults, and docstrings.

FIXES APPLIED:

  1. LR scheduler — ReduceLROnPlateau (patience=5, factor=0.5, min_lr=1e-6).
     Why: A flat learning rate at 1e-3 for 100 epochs means the model makes
     the same size adjustments even when it's close to optimal. This causes
     the model to plateau around epoch 20-30 and never converge to the best
     solution. The scheduler watches val_auroc; if it doesn't improve for 5
     epochs, it halves the learning rate, allowing finer convergence.

  2. Early stopping — patience=15 epochs.
     Why: Without early stopping, training runs all 100 epochs even if the
     model peaked at epoch 25 and is now overfitting (memorizing training
     data instead of learning patterns). This wastes 75 epochs of compute
     time and risks degrading the final saved model. The best checkpoint is
     always preserved since we save on improvement.

  3. Gradient clipping — max_norm=1.0 before optimizer.step().
     Why: Medical signal data is noisy. A batch with bad windows can produce
     an extremely large gradient that blows up model weights, causing NaN
     loss or unstable training. Clipping caps the gradient magnitude at 1.0.
     Standard practice in every production medical ML pipeline.

  4. Memory-mapped cache loading — np.load(..., mmap_mode="r").
     Why: PrecomputedDataset was loading entire numpy arrays into RAM on init
     (train_short.npy alone is ~1.5 GB at 157K×2500 float32). With train +
     val + HRV + labels, peak RAM was ~4+ GB before training even started.
     Memory-mapping reads data from disk on demand; the OS page cache handles
     the rest. Reduces peak RAM usage significantly.

  5. Fixed t.size bug in on-the-fly training path (train.py line 134).
     Why: torch.Tensor.size is a method (returns torch.Size object), not an
     int like numpy's ndarray.size property. The expression max_len - t.size
     would crash with a TypeError. Changed to t.numel() which returns the
     total element count as an int. Only affects the on-the-fly path (not
     --use-cache), but should still be correct.

  6. TransformerConfig default seq_len 10 → 5 (transformer.py).
     Why: The dataclass default was 10 from before the subwindow_sec change
     (300/30=10 → 300/60=5). build_model.py overrides from config so runtime
     was correct, but anyone constructing TransformerConfig() without
     arguments would get the wrong default.

  7. Fixed stale docstrings in ensemble.py, rnn.py, transformer.py.
     Why: Documentation said seq_len=10 in multiple places. Updated to
     generic "seq_len" since the actual value comes from config.

Tests: 33/33 passing after all fixes.

--- 2.12 MIMIC-III Cross-Dataset Validation Setup (2026-03-14) ---

PURPOSE: The training val_auroc=0.9999 is suspiciously high. With only
41 PhysioNet records (23 afdb + 18 nsrdb), the model likely exploits
non-physiological dataset artifacts (record length patterns, noise
profiles, equipment differences) rather than learning pure AF physiology.
MIMIC-III cross-dataset validation (NFR-3.1: <5% F1 degradation) is the
real test of whether the model generalizes.

MIMIC-III DATA STRUCTURE:
  The user downloaded the clinical MIMIC-III database (relational tables:
  admissions, labs, diagnoses, etc.) — NOT raw ECG waveforms. The clinical
  tables contain ICD diagnosis codes but no signal data. Separately,
  PhysioNet hosts the MIMIC-III Waveform Database Matched Subset which
  links ICU waveform recordings to clinical records.

  - Clinical MIMIC-III: DIAGNOSES_ICD.csv has 46,520 patients, 10,271
    with AF diagnosis (ICD-9 code 42731).
  - Waveform Matched Subset: 10,282 patients have waveform recordings.
  - Overlap: 3,035 AF patients and 7,247 non-AF patients have both
    clinical diagnoses and waveform recordings.

DOWNLOAD APPROACH:
  Created src/data/download_mimic3_waveforms.py that:
  1. Reads DIAGNOSES_ICD.csv to identify AF (42731) vs non-AF patients
  2. Cross-references with MIMIC-III Waveform Matched Subset RECORDS list
  3. For each selected patient, checks all available waveform records:
     - Skips "numerics" records (fs=1 Hz — these are vital sign trends,
       not ECG waveforms)
     - Requires fs>1 Hz (actual waveforms are typically 125 Hz)
     - Requires at least one ECG channel (II, I, V, MCL, etc.)
     - Minimum 30 seconds duration (was 300s, reduced because many MIMIC
       records are short segments; our CNN only needs 10s, and partial
       HRV is acceptable for validation)
     - Picks the longest qualifying record per patient
  4. Downloads .hea + .dat files to data/raw/mimic3/
  5. Renames files to p{subject_id}_{record} to avoid collisions
  6. Writes .label files (1=AF, 0=non-AF) from ICD diagnosis

  Target: 30 AF + 30 non-AF patients. Oversamples 3x to account for
  patients without qualifying waveform records.

WHY 30 SECONDS MINIMUM (not 5 minutes):
  The 5-minute window is the gold standard for HRV analysis (ESC/NASPE
  1996 guidelines). However, for model validation:
  - The CNN branch only needs 10 seconds of raw ECG
  - Records shorter than 5 minutes will have partial/zero HRV features
    (NaN→0), but the CNN still produces valid predictions
  - The model was trained to handle NaN HRV (7% of training rows were NaN)
  - Getting real cross-dataset validation on 60 patients is more valuable
    than getting perfect-length records on 10 patients
  - Records with >=5 minutes will get full HRV; shorter ones test whether
    the model degrades gracefully with partial features

STATUS: Download complete. 30 AF + 30 non-AF WFDB records in data/raw/mimic3/.

--- 2.14 NaN Logit Root Cause + Fix (2026-03-14) ---

  10 of 60 MIMIC-III records produced NaN logits during cross-dataset eval.

  ROOT CAUSE: MIMIC-III ICU waveform recordings (WFDB p_signal) contain NaN
  values for missing/invalid samples — equipment disconnections, lead-off
  events, and signal gaps that are common in ICU settings. These NaN values
  propagate through: wavelet denoising → peak detection → HRV → model → NaN
  logit. PhysioNet clean databases (afdb, nsrdb) never have NaN in signals.

  FIX: Added np.nan_to_num(signal, nan=0.0) in parse_mimic3_wfdb_record()
  immediately after channel selection. This zeros out missing samples at parse
  time, before any downstream processing. Zero-fill is acceptable because:
  - ICU signal gaps are typically short (< 1s)
  - Wavelet denoising smooths over brief zero segments
  - The alternative (skipping records) would lose ~17% of holdout data

  Also added: holdout_path parameter to evaluate_mimic3() and --holdout CLI
  flag for restricting evaluation to reserved holdout subjects only.

  RESULT (2026-03-14): 60/60 valid logits, 0 NaN. Clean baseline:
    AUROC=0.6656, F1=0.6286, Sensitivity=0.7333, Specificity=0.4000
    NFR-3.1 still FAIL (expected — data expansion needed, not just NaN fix).

--- 2.18 HRV Pipeline Bug Fixes: inf sampen + short record fallback (2026-03-15) ---

  Cache rebuild (Step 21b) completed but inspection revealed two bugs that
  crippled the HRV branch of the ensemble model:

  BUG 1 — inf sampen poisons scaler (100% of feature 5 zeroed out):
    nk.entropy_sample() returns inf for 7 out of 28,404 valid sampen values
    (when no template match is found). compute_hrv_nonlinear() stored inf as-is.
    fit_scaler() only filtered NaN, not inf → scaler.mean_[5] = inf,
    scaler.scale_[5] = nan. transform() then computed (x - inf) / nan = NaN
    for ALL sampen values → nan_to_num → 0.0. The entire sampen feature was
    zeroed out across the entire dataset.

  BUG 2 — 89.5% of records too short for HRV subwindows (37.7% all-NaN):
    Challenge 2017 records are 30-60s. With subwindow_sec=60, pipeline.py
    computed n_available = signal_samples // (fs * 60) = 0 for anything < 60s.
    This returned all-NaN (5,7) HRV. 3,783 of 10,046 train windows (37.7%)
    had completely empty HRV — the RNN/Transformer branches learned nothing
    from them.

  FIXES APPLIED:

    1. hrv_nonlinear.py: Added np.isfinite() guard after sampen and dfa_alpha1
       computation. Any inf value is clamped to NaN (the pipeline's established
       "missing data" sentinel).

    2. scaler.py: Changed ~np.isnan() to np.isfinite() in both fit_scaler()
       and transform(). This filters NaN, +inf, and -inf in a single call.
       Defense in depth: even if a new feature source introduces inf, the
       scaler cannot be corrupted.

    3. pipeline.py: When n_available == 0 (signal shorter than subwindow_sec),
       compute HRV over the full available signal as a single pseudo-window.
       Fill timestep 0 with whatever features are computable (time-domain if
       >= 5 RR intervals, freq-domain if >= 32, nonlinear if >= 10). Timesteps
       1-4 remain NaN → 0 after scaling. Output shape stays (5, 7).

    4. tests/test_preprocessing.py: Updated 1 existing test, added 8 new tests:
       - test_short_record_60s_has_partial_hrv (updated from all-NaN assertion)
       - test_short_record_30s_partial_hrv
       - test_very_short_record_5s_all_nan
       - test_nonlinear_inf_clamped_to_nan
       - test_fit_scaler_ignores_inf
       - test_transform_treats_inf_as_nan
       - test_e2e_inf_sampen_survives_scaling
       - test_e2e_short_record_nonzero_after_scaling

3. RATIONALE FOR KEY CHOICES
--------------------------------------------------------------------------------

- Split by subject_id (70/15/15): Prevents information leakage between
  train/val/test and satisfies TR-1.1 (holdout by patient). Same split file
  used by dataloaders and (when implemented) train/evaluate.

- Single config.yaml: One place for LSL rate (250 Hz), HRV windows (30 s,
  5 min), wavelet params, artifact thresholds, watchdog limits, paths, and
  model dimensions. Enables reproducibility and traceability to FR/NFR/TR.

- 10 s waveform + 5 min HRV: Short window for morphology (CNN); long window
  for temporal/autonomic state (RNN/Transformer). Matches FR-2.2 and
  config (waveform_sec, hrv_window_sec, subwindow_sec).

- Hybrid ensemble (CNN + RNN + Transformer): Aligns with Aim 2 multi-architecture
  targets (CNN cross-dataset, RNN sequence, Transformer optimization, ensemble
  fusion). Single logit keeps Phase 1 scope to binary classification (e.g. AF
  vs non-AF or stimulation trigger).

- Wavelet (CWT, cmor): Documented in Aim 2 for denoising and adaptive filtering;
  configurable family/scale for tuning without code change.

- Artifact rejection (MAD + R–R %): Simple, interpretable rules; thresholds in
  config to be updated after validation so we don’t over-reject or under-reject.
  WARNING (2026-03-13): The 25% R-R deviation threshold systematically rejects
  AF windows because AF is characterized by irregular R-R. See Section 2.9 for
  diagnosis and recommended fixes.

- Scaler fit on train only + persist: Prevents leakage; inference uses same
  scaling as training (NFR-3.1, generalizability).

- PCA module for multi-channel → 1 channel: Prepares for Galea (multi-channel)
  to Sparrow (single-channel) and TR-2.3 channel-stripping tests without
  changing core model API.

- LSL and hardware deferred: Phase 1 focuses on data, preprocessing, and models
  with offline datasets; LSL and Sparrow/watchdog/state machine are scheduled
  for Live Integration (Weeks 6–8) so algorithm validation is not blocked by
  hardware availability.

- MockSparrow in Phase 1: All stimulation requests will go through the
  watchdog (no direct trigger_stim from AI). Phase 1 uses a mock to log
  commands and validate the control path without physical device.

- Precompute workers and config path: Worker processes may have a different
  current working directory than the main process, so passing a relative
  config_path (e.g. "config.yaml") could lead to missing or wrong config and
  all-NaN HRV; resolving to an absolute path in the main process and passing
  that to workers ensures consistent config and valid HRV when using --workers > 1.
